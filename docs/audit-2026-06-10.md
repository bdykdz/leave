# Repository Audit & Improvement Plan — Leave Management System

**Audited:** `/opt/leave-management/leave`, branch `feature/ralph-comprehensive-update`, 2026-06-10.
Analysis only — no code was modified during the audit. Findings marked **[verified]** were confirmed directly; the rest were produced by deep file-level review and spot-checked.

> **Post-audit decisions from the owner (2026-06-10):**
> - Deployment is **direct to prod** via `docker-compose.production.yml`; Coolify/Vercel/Nixpacks/Hetzner paths are dead and should be removed.
> - UAT is barely used.

---

## 1. Executive Summary

**Overall health grade: C–.** The application is functionally rich, runs in production with real employee data, and has genuinely good bones — consistent authorization checks, Zod validation, Prisma transactions around balance math, and an unusually broad Playwright test estate. But its safety systems are largely theater: the build ignores all 172 TypeScript errors, every meaningful ESLint rule is turned off, two of three CI pipelines call npm scripts that don't exist, and — worst of all — **the production container runs `prisma db push --accept-data-loss` on every startup against the production database**. The core approval state machine is copy-pasted across four routes with divergent behavior, and the money-adjacent logic (leave balances, pro-rata, rollover) has zero unit tests.

**Top 3 risks:** (1) `start.sh` can silently destroy production data on any schema drift; (2) 172 type errors shipping to production, several being real crash paths; (3) approval logic divergence across duplicated routes causing stuck/inconsistent approvals (a pattern already visible in the recent fix-commit history).

**Top 3 opportunities:** (1) a one-day CI/startup fix converts the existing test estate into a real safety net; (2) a unit-test harness over `lib/services/` makes the riskiest code cheap to change; (3) consolidating the approval flow into one service eliminates the bug class that dominates recent commits.

## 2. Repo Map

**Scale:** ~104k lines across `app/ lib/ components/`; **222 API route files** under `app/api/`; **39 Prisma models**; 41 Playwright spec files (~19k lines).

**Key directories:**

## 3. Audit Report

### 3.1 Critical

**C1. Production startup runs `prisma db push --accept-data-loss`** [verified — fact]
`start.sh:13`, executed as `CMD` from `Dockerfile:69` on every production container start. If the deployed Prisma schema ever diverges from the production DB (e.g., a column renamed in code before a hand-written migration lands), `db push` will reconcile by **dropping/recreating data without prompting**. This directly contradicts the team's stated "hand-write migrations + `migrate deploy`" workflow and CLAUDE.md. Backups are local-only (same host), so the blast radius of one bad deploy is total. This is the single most dangerous line in the repository.

**C2. All compile-time and lint safety is disabled, and 172 type errors ship** [verified — fact]
`next.config.mjs:6-11` sets `eslint.ignoreDuringBuilds: true` and `typescript.ignoreBuildErrors: true`; `eslint.config.mjs:16-31` turns off `no-explicit-any`, `no-unused-vars`, `no-console`, `no-fallthrough`, etc. `tsc --noEmit` reports **172 errors**, and a sample are genuine runtime crashes, e.g.:
- `app/api/admin/migrate-selected-dates/route.ts:75` reads `request.user.firstName` without including `user` in the query → undefined-property crash (fact).
- `app/api/executive/cancel-leave/[id]/route.ts:208,229,247` passes possibly-null `firstName` into email calls (fact).
- `app/api/admin/manual-work-trip-request/route.ts:185` logs entity `'WORK_TRIP_REQUEST'` not present in the audit enum → audit trail gap for work trips (fact).

Consequence: the compiler already knows about production bugs and is being ignored — consistent with the recent commit history being dominated by "fix Prisma schema mismatches"-type firefighting.

**C3. CI quality gates are broken or vacuous** [verified — fact]
`.github/workflows/deploy-staging.yml:33,36` and `deploy-uat.yml:33,36` run `npm test` and `npm run test:integration` — **neither script exists in package.json**, so those pipelines fail at the test step. The production workflow (`deploy-production.yml:27-30`) runs only `npm run build` (which can't fail on TS/lint per C2) and `test:e2e --grep="critical"` with no database, no app server, and no `webServer` in any Playwright config (`playwright.config.ts:10` expects a live instance at `localhost:8082`) — it cannot meaningfully pass as written. Net effect: **nothing automated stands between a commit on `main` and production.**

### 3.2 High

**H1. Approval state machine duplicated across four routes with divergent behavior** (fact + judgment)
Status transitions are inlined in `app/api/manager/team/approve-request/[requestId]/route.ts` (914 lines — leave + nested WFH + work-trip handlers), `app/api/executive/approve-request/[requestId]/route.ts`, and HR routes. Verified divergences: delegation support (`DelegationService.getActiveDelegatorIdsFor`) and escalation-fallback cleanup (manager route lines ~279-306) exist only in the manager route; the executive route lacks the "already approved" re-check the manager route has. `workflow-engine.ts` is unused by all of them [verified]. Consequence: every approval bug must be found and fixed N times — exactly the pattern in commits `50a2410` (executive work-trip approvals hanging) and `abcddb0`.

**H2. Zero unit tests on money-adjacent logic** (fact)
No jest/vitest exists anywhere (package.json has no unit runner). `leave-balance-service.ts`, `pro-rata-service.ts` (FTE math), `leave-rollover-service.ts` (carry-forward expiry), `escalation-service.ts` (868 lines), and `delegation-service.ts` are exercised only through brittle E2E flows. Edge cases (mid-year starts, carry-forward FIFO, year boundaries) are unverifiable in isolation. These services compute what is effectively compensation.

**H3. E2E suite is broad but brittle** (fact)
326 `waitForTimeout` calls; hardcoded staging credentials (`employee@staging.local` / `admin123` in `e2e/employee/leave-request.spec.ts:17-20`); loose assertions (`expect(body).toBeVisible()` *after submitting a leave request*, leave-request.spec.ts:404); all specs depend on seeded staging data and a pre-running server. The suite's pass signal is weaker than its 19k LOC suggests.

**H4. Secrets on disk in untracked compose files; weak defaults** (fact)
`docker-compose.uat.yml` / `docker-compose.staging.yml` / `docker-compose.yml` are **not git-tracked and never were committed** [verified]. But they sit in plaintext on the production host with `NEXTAUTH_SECRET=uat-secret-change-me`, `SETUP_PASSWORD=admin123`, `MINIO_SECRET_KEY=minioadmin123`, `SHOW_DEV_LOGIN=true`. `docker-compose.production.yml` correctly uses env files and binds ports to `127.0.0.1` (strength). Residual risks: host compromise, copy-paste of `admin123` into prod, and a UAT instance with dev-login enabled.

**H5. Missing DB indexes on hottest tables** (fact)
`prisma/schema.prisma`: `LeaveRequest`, `Approval`, `Notification`, `AuditLog` have **no `@@index`** despite every dashboard filtering on `status`, `userId`, `approverId`, date ranges, and `userId+isRead`. (WFH/WorkTrip models do have indexes — the inconsistency suggests they were added later and the original models never got them.) At current scale this is latent, but it costs one safe additive migration to fix.

**H6. N+1 query storms in analytics** (fact)
`lib/services/analytics-service.ts`: `getTeamCoverageAnalytics` (lines ~420-471) runs 2 queries **per day** in a 30-day loop; `getSeasonalAnalytics` (~336-403) runs 4+ queries per month × 12 plus a per-leave-type N+1; `getDepartmentAnalytics` (~192-228) queries 3-4× per department. The Redis `cache-service.ts` exists but these hot paths don't use it (cache is largely decorative). Executive dashboard latency degrades linearly with data growth.

**H7. Unstructured logging + unvalidated environment** (fact)
694 `console.*` occurrences across 226 files in `app/ lib/` despite a PII-redacting structured `lib/logger.ts` (which itself suppresses `info` in production, logger.ts:98-101). `lib/env.ts` falls back to empty strings for Azure AD config; ~47 files read `process.env` directly with silent fallbacks (`lib/minio.ts`, email service) — missing config surfaces as mysterious runtime failures rather than a startup error.

### 3.3 Medium

- **M1. ~2,100 lines of duplicated component:** `components/admin/ManualRequestEntry.tsx` (1,098) vs `components/hr/ManualRequestEntry.tsx` (1,091) differ by ~30 lines (endpoints + labels) (fact). Same pattern: `approval-dialog.tsx` vs `approval-dialog-v2.tsx` (v2 is superior; v1 likely dead).
- **M2. God components:** `app/manager/page.tsx` (2,544 lines, ~68 useState hooks, 4 tab systems); `lib/email-service.ts` (1,478 lines of inline HTML templates, English-only — no Romanian emails despite the app being bilingual) (fact + judgment).
- **M3. Timing-unsafe secret comparisons:** `app/api/setup/auth/route.ts:17` (SETUP_PASSWORD, `!==`) and `app/api/cron/escalation/route.ts:12` (CRON_SECRET) — contrast with `test-auth`'s constant-time compare which proves the team knows the pattern (fact; low practical exploitability, trivial fix).
- **M4. `/api/debug/leave-request/[id]`** is HR/ADMIN-gated but has no environment gate — a data-exfil convenience endpoint live in production (fact).
- **M5. MANAGER role can list all users with phone/DoB** via `app/api/admin/users/route.ts:24` allowing `['ADMIN','HR','EXECUTIVE','MANAGER']` (fact). **Owner decision: this is a feature — keep.**
- **M6. In-process node-cron via `instrumentation.ts`** self-fetching its own API: duplicate execution on any multi-instance future; given the escalation cron's history of silently cancelling HR entries (commit `abcddb0`), this subsystem has bitten before (fact + judgment). **Owner decision: auto-cancel behavior is a feature — keep.**
- **M7. Unbounded queries:** `app/api/hr/analytics/export/route.ts:71` fetches all matching leave requests with includes and builds HTML in-process; `app/api/notifications/route.ts` `limit` param unclamped (fact).
- **M8. Dependency hygiene:** 6 moderate CVEs (`npm audit`: PostCSS via next, uuid via next-auth); 11 packages pinned to `"latest"` (radix-ui ×9, cmdk, recharts); `xlsx@0.20.3` from a non-npm CDN tarball; Prisma 6.9 vs 7.x available (fact).
- **M9. Deployment sprawl + docs:** 10 compose files, 4 Dockerfiles, plus coolify.yaml, nixpacks.toml, vercel.json, deploy-hetzner.sh — at most one path is authoritative (owner confirms: only `docker-compose.production.yml` is real). **No README.md.** ~15 root markdown docs of mixed staleness (fact).
- **M10. In-memory, per-instance rate limiter** keyed on spoofable `x-forwarded-for` (middleware.ts:5-42); acceptable behind Cloudflare on one instance (fact + judgment).

### 3.4 Low

Dead/junk files tracked in git: `Dockerfile.old`, `tsconfig.tsbuildinfo`, `app/admin-old/`; untracked root clutter (`cloudflared.deb` 18MB, `e.yml`, `.bak` files). `lib/i18n.ts` at 2,403 lines is fine for its purpose. Setup endpoint's `secure` cookie flag keyed off `APP_ENV` rather than HTTPS.

### 3.5 Strengths (preserve these)

1. **Transactional integrity where it matters most:** `app/api/leave-requests/route.ts:458-584` does overlap-check, balance re-check, and request-number generation *inside* `prisma.$transaction`.
2. **Authorization is consistently real:** sampled routes check session + role + ownership; `app/api/documents/[documentId]/route.ts:94-129` implements a proper owner/role/manager-hierarchy/signer access matrix; document path handler sanitizes traversal robustly.
3. **No raw SQL anywhere** except a literal `SELECT 1` health check — Prisma ORM throughout [verified].
4. **Resilience pattern:** `safeAsync` wraps email/notification sends so external failures never fail approvals.
5. **Test breadth:** security (163 tests with real behavioral assertions), a11y (Axe, 119 tests), contract (128 tests), visual baselines.
6. **Operationally sane production config:** env-file secrets, localhost-bound ports, additive-only migration history, daily backups, Sentry with PII filtering.

## 4. Improvement Strategy

**Theme 1 — The safety systems are fake; make them real.** (C1, C2, C3, H7.) Target: `tsc --noEmit` passes and blocks CI; CI calls scripts that exist; production startup runs `prisma migrate deploy`, never `db push`. Principle: a check that doesn't block is documentation, not a check.

**Theme 2 — One state machine, written once, tested in isolation.** (H1, H2.) Target: a single `ApprovalService` for all three request types; vitest unit suite over balance/pro-rata/rollover/escalation with ≥80% coverage. Principle: code that moves paid leave earns isolated tests before its next refactor.

**Theme 3 — Duplication is the team's default reuse mechanism; replace it with parameterization.** (H1, M1, M2.)

**Theme 4 — Shrink the operational surface to one true path.** (H4, M9, H7-env.) Target: README + one compose file per live environment; Zod-validated env that fails fast; secrets rotated off `admin123`-class defaults.

**Explicitly NOT fixing now:** Prisma 7/Next major upgrades (churn > payoff until test net exists); Redis-backed rate limiting (single instance behind Cloudflare); full god-component decomposition and email-template extraction (opportunistic only); i18n file structure; ReportPortal/Allure infra.

**Definition of done:** CI blocks on lint + typecheck + unit + smoke · `tsc --noEmit` = 0 · `start.sh` contains no `db push` · core service coverage ≥ 80% · one approval code path · zero Critical/High security findings · restore-from-backup demonstrated · new-dev setup ≤ 30 min from README.
